## Environment

Configure the following locally and in the Vercel project:

```dotenv
NEXT_PUBLIC_SANITY_PROJECT_ID=0amqcii5
NEXT_PUBLIC_SANITY_DATASET=production
NEXT_PUBLIC_SITE_URL=https://themartyrschurch.com
SANITY_REVALIDATE_SECRET=<long-random-secret>
```

`SANITY_API_WRITE_TOKEN` is only needed to run the seed script. Do not expose it
with a `NEXT_PUBLIC_` prefix, commit it, or install it in the browser.
`SANITY_API_READ_TOKEN` is optional for a private dataset and is server-only.

## Initial content

Run `npm run cms:seed:check` to inspect the seed count without changing Sanity.
Run `npm run cms:seed` with a write token to create the existing website content.
The seed uses `createIfNotExists`; rerunning it never replaces editor changes.

The checked-in JSON files are a migration snapshot. Source defaults remain in
the actual components so the website stays populated without credentials,
when a request fails, or when an editor leaves a field blank. Do not rerun the
one-time `prepare-cms.cjs` migration on already migrated source files.

## Editing

- **Page & section copy:** headings, paragraphs, button copy, modal and form copy.
- **Website images:** replace existing photo slots and supply alt text.
- **Website links:** destinations for links already used by the website.
- **Page titles & descriptions:** browser titles and search descriptions.
- **Collections:** navigation, footer links, leaders, ministries, history,
  resources, testimonies, mission activities/counters/gallery, service schedules,
  social profiles, introduction frames, and photos.

Items can be added and reordered. Empty collections retain the local list.
Missing fields inherit the local fallback; a valid `0` or `false` is preserved.
Use leaders' biography and uploaded image fields for the featured leadership
profile. Add a PDF to a resource to enable its download link.
Publish a document to expose it on the public site; drafts are not queried.
YouTube service videos remain sourced from the existing YouTube API, not copied
into Sanity. Form delivery remains server configuration, not editable content.

## Cache and publication

The server makes one deduplicated, cached Sanity query for the shared content
snapshot. Pages use 300-second ISR, with a shorter existing YouTube-live cache
on Services. The editor is dynamic and is excluded from indexing/analytics.

Create a Sanity webhook for published create/update/delete operations:

- URL: `https://themartyrschurch.com/api/revalidate`
- Method: `POST`
- Filter: `!(_id in path("drafts.**"))`
- Header: `Authorization: Bearer <SANITY_REVALIDATE_SECRET>`

Use the same secret in Vercel. The webhook expires the tagged content snapshot
and invalidates public routes; they regenerate on their next request. Without
the webhook, the timed ISR refresh still works. In-flight pages need a refresh
to show newly published content.

## Vercel Analytics and SEO

Enable Web Analytics for the Vercel project and deploy. The Next.js Analytics
component handles public navigation and removes query strings/hashes from page
view URLs. Studio visits are excluded. No delivery to Vercel has been verified
until the application is deployed and an event appears in the dashboard.

Canonical URLs use the production domain. Sitemap, robots, Open Graph, and
Twitter metadata are generated by Next.js. Preview deployments request noindex.
